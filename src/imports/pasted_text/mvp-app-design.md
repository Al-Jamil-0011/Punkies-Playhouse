Create a complete, simple, modern mobile app MVP with a clean and intuitive user experience.

IMPORTANT: Keep this application AS SIMPLE AS POSSIBLE.

Do not over-engineer the product. Do not add unnecessary screens, features, dashboards, charts, filters, complicated settings, or long onboarding flows.

The goal is to create a small but polished mobile application that looks realistic, professional, and ready to present to a client.

## GENERAL DIRECTION

Design a mobile application for iOS and Android using a modern smartphone frame.

The app should feel:

* Simple
* Clean
* Friendly
* Modern
* Trustworthy
* Easy to understand
* Easy to navigate
* Professional enough for a real production application

Prioritize usability over decoration.

Use generous white space, clear typography, large touch-friendly controls, simple cards, and obvious calls to action.

## BRANDING

Create a simple temporary brand identity for the application.

You have creative freedom to:

* Create a suitable app name if one is not provided
* Create a simple logo/brand mark
* Select the primary brand color
* Select secondary/accent colors
* Choose appropriate neutral colors
* Choose a suitable modern font

Keep the logo extremely simple.

Use a clean symbol + wordmark approach if appropriate.

Do not make the branding overly corporate, luxurious, futuristic, or complicated.

Choose colors based on what best fits a simple, trustworthy, modern mobile application.

Maintain good accessibility and text contrast.

## DESIGN STYLE

Use a light theme as the primary theme.

Use:

* White or very light backgrounds
* One strong primary brand color
* One optional accent color
* Dark neutral text
* Light neutral borders
* Subtle shadows
* Rounded corners
* Simple line icons
* Clean modern typography

Avoid excessive:

* Gradients
* Glassmorphism
* Shadows
* Illustrations
* Decorative graphics
* Animations
* Different colors
* Card-on-card layouts

The design should look like a real app, not a UI design experiment.

## APP STRUCTURE

Keep the application to approximately 6–8 essential screens.

Create only the screens necessary to demonstrate a complete user journey.

### 1. SPLASH SCREEN

Create a very simple splash screen.

Include:

* Logo
* App name
* Clean background

Nothing else is required.

### 2. WELCOME / GET STARTED

Create one simple welcome screen.

Include:

* Logo or small visual
* Short headline
* One sentence explaining the app
* Primary "Get Started" button
* "Already have an account? Log In"

Do NOT create multiple onboarding slides.

One welcome screen is enough.

### 3. LOGIN / SIGN UP

Create simple authentication.

LOGIN:

* Email
* Password
* Forgot Password
* Log In button
* Sign Up link

SIGN UP:

* Full Name
* Email
* Password
* Create Account button

Do not request unnecessary information.

Keep both screens extremely clean.

### 4. HOME

Create a simple Home screen.

This should be the main screen after authentication.

The top area should contain:

* Simple greeting
* User name
* Small profile avatar

Below this, clearly show the PRIMARY PURPOSE/ACTION of the application.

The most important thing the user can do should be immediately visible.

Use one large primary CTA.

Below the primary action, show only a small amount of useful information such as:

* Recent activity
* Current status
* Recent items

Do not create an analytics dashboard.

Do not use charts.

Do not fill the screen with cards.

Keep Home extremely easy to scan.

### 5. MAIN ACTION SCREEN

Create one screen dedicated to the application's primary action.

The user should be able to complete the main task with minimal input.

Only request information that is absolutely necessary.

Use:

* Clear title
* Short supporting text
* Simple fields/selections
* One primary CTA

Try to keep the entire process on one screen.

Avoid multi-step forms unless absolutely necessary.

### 6. CONFIRMATION / SUCCESS

After completing the primary action, show a simple success state.

Include:

* Success icon
* "Done!" or another appropriate success headline
* Short confirmation message
* Important summary/details
* "Back to Home" button

Keep this screen positive and minimal.

### 7. ACTIVITY / HISTORY

Create one simple screen where the user can see previous activity/items.

Use a clean vertical list.

Each item can contain:

* Title
* Date
* Short detail
* Status

Allow tapping an item to view basic details.

Do not add advanced search/filtering unless genuinely necessary.

### 8. PROFILE

Create one simple Profile screen.

Include:

* Avatar
* Name
* Email
* Edit Profile
* Notifications toggle if appropriate
* Help / Support
* Log Out

Avoid creating a large settings system.

## NAVIGATION

Use a simple bottom navigation.

Maximum 3 items:

Home | Activity | Profile

Use simple recognizable icons.

Highlight the active navigation item clearly.

Do not add more navigation tabs unless absolutely necessary.

## USER FLOW

Create the prototype around this simple journey:

Splash
→ Welcome
→ Sign Up / Login
→ Home
→ Main Action
→ Success
→ Home

Secondary flow:

Home
→ Activity
→ Activity Detail

And:

Home
→ Profile
→ Edit Profile

Keep navigation predictable.

The user should never wonder where to go next.

## INTERACTION DESIGN

Make important buttons and navigation elements functional in the prototype.

Add appropriate interactions for:

* Get Started
* Login
* Sign Up
* Main CTA
* Submit/Confirm
* Back
* Bottom navigation
* Activity items
* Edit Profile
* Logout

Use subtle transitions.

Do not use unnecessary animations.

## COMPONENTS

Create only the reusable components needed for this application:

* Primary Button
* Secondary/Text Button
* Input Field
* App Header
* Bottom Navigation
* List Item
* Simple Card
* Avatar
* Status Badge
* Success State

Use consistent components throughout the application.

## SPACING & LAYOUT

Use a consistent 8px-based spacing system.

Keep generous spacing between sections.

Use comfortable mobile margins.

Use Auto Layout wherever appropriate.

Maintain consistent:

* Button heights
* Input heights
* Corner radius
* Typography
* Icon sizes
* Horizontal padding
* Section spacing

## TYPOGRAPHY

Choose one modern sans-serif font.

Create a very simple hierarchy:

* Large page title
* Section heading
* Body
* Small secondary text
* Button text

Do not use too many font sizes or weights.

## UX RULES

Follow these rules throughout the design:

1. One obvious primary action per screen.
2. Minimize the number of taps required.
3. Minimize user input.
4. Use familiar mobile UI patterns.
5. Keep text short.
6. Avoid unnecessary screens.
7. Avoid unnecessary features.
8. Keep navigation consistent.
9. Make buttons clearly recognizable.
10. Make important information immediately visible.
11. Use plain, understandable language.
12. Keep the overall experience beginner-friendly.

## IMPORTANT SIMPLIFICATION RULE

Whenever there are two possible approaches, choose the SIMPLER approach.

For example:

Instead of 3 onboarding screens → use 1.

Instead of 5 navigation tabs → use 3.

Instead of a multi-step form → use one screen.

Instead of a complex dashboard → use a simple Home screen.

Instead of separate notification/settings pages → include basic options inside Profile.

Instead of multiple confirmation screens → use one success screen.

Instead of advanced filtering → use a simple list.

Do not create functionality simply to make the app appear larger.

## FINAL OUTPUT

Generate a cohesive mobile app design with approximately 6–8 core screens.

The screens should visually belong to the same product and use the same design system.

Organize the Figma output clearly.

Create:

* Main app screens
* Reusable components
* Consistent styles
* Auto Layout
* Clickable prototype connections

Use realistic sample content rather than Lorem Ipsum.

The final result should feel like a SMALL, POLISHED MVP that a client can easily understand and that developers can realistically build.

Most importantly:

SIMPLE > COMPLEX

USABILITY > DECORATION

CLEAR USER FLOW > NUMBER OF FEATURES

Do not add unnecessary functionality just to fill the interface.
